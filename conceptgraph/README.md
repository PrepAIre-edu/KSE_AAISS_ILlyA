# `conceptgraph` — агент, що перетворює матеріали на концепти та зв'язки

Python-пакет на Anthropic API. На вході папка з дампом курсу, на виході граф концептів + CSV/JSON/seed SQL/HTML. Той самий результат, що ми зібрали руками, але як одна команда.

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...

python -m conceptgraph plan  ~/Downloads/MIT --out ./build              # без API-викликів
python -m conceptgraph run   ~/Downloads/MIT --out ./build --courses AGAI  # пробний, один курс
python -m conceptgraph run   ~/Downloads/MIT --out ./build              # усе
python -m conceptgraph report --out ./build
```

## Стадії

```
scan ──▶ textract ──▶ bundle ──┬──▶ extract (MAP) ──▶ consolidate (REDUCE) ──▶ graph ──▶ validate ──▶ export
         детерміновані          │    LLM, паралельно      LLM, глобальний          детермін.   gate
                                └─ 61 юніт, 15 батчів                контекст
```

Кожна стадія пише свій артефакт і **пропускається, якщо артефакт уже є**. Тому `run` можна перервати й запустити знову — він продовжить. `--force extract` перероблює конкретну стадію, `--stop-after bundle` зупиняє раніше.

**Детерміновані стадії** (`scan`, `textract`, `bundle`, `graph`) не викликають модель узагалі. Однакові входи завжди дають однаковий граф — саме тому пайплайн можна тестувати.

## Що робить LLM, а що ні

| | |
|---|---|
| **MAP — `extract`** | 15 паралельних викликів, кожен читає ~160 тис. символів (кілька юнітів) і повертає 5–10 концептів на юніт з дослівними цитатами й `rel_path`. Модель за замовчуванням — Sonnet: викликів багато, входи великі. |
| **REDUCE — `consolidate`** | Те, що я робив руками. Три проходи, найдешевший перший (нижче). Модель — Opus: викликів мало, потрібне судження про весь каталог. |
| **`graph`** | Чиста алгебра: резолв аліасів, дедуп, злиття суперечливих ребер, **розрив циклів у `prerequisite`**. Без моделі. |
| **`validate`** | Без моделі. Перевіряє дослівність цитат проти витягнутого тексту. |

### Чому консолідація — три проходи

Це найтонше місце. Екстрактори працюють паралельно й жоден не бачить каталогу цілком, тому один концепт отримує два слаги, а граф розпадається на компоненти.

1. **R1 `merge-adjudicate`** — детермінований префільтр дає пари-кандидати (аліас-матч, схожість назв, перетин тріграм визначень), LLM судить кожну. Дешево, висока точність. Вартість `O(кандидатів)`, а не `O(n²)`.
2. **R2 `merge-propose`** — LLM сам шукає дублікати у слайсі каталогу. Це потрібно, бо **лексичний фільтр має стелю**: `computer-as-tool` і `ai-as-tool` означають те саме, але не мають ані спільних слів, ані спільних аліасів, ані достатнього перетину визначень. Жоден лексичний метод їх не зловить.
3. **R3 `bridge`** — нові ребра. Кожен виклик бачить слайс у деталях, наявні ребра слайса (щоб не дублювати) і **глобальний індекс слагів** (~3 тис. токенів на 400 концептів — дешево). Саме це зшиває компоненти й дає міжкурсові зв'язки.

Префільтр знаходить 32 кандидати на 436 концептів; R2 добирає решту. Обидва проходи повертають вердикти, які об'єднуються через union-find, тож транзитивні дублікати (`a≡b`, `b≡c`) склеюються в одну групу.

## Гарантії від коду, а не від промпту

Промптом просять — кодом забезпечують. Ці інваріанти тримаються незалежно від того, що поверне модель:

- **Структурований вихід.** Кожен виклик іде через `tool_use` з `input_schema`, згенерованою з pydantic-моделі. Ми ніколи не парсимо прозу і не зрізаємо ```-фенси. Якщо модель порушила схему — їй показують `ValidationError` і просять виправити.
- **Цитата належить файлу.** `rel_path`, якого нема серед файлів юніта, відкидається (у `graph.notes`). Модель не може приписати цитату чужому файлу.
- **`prerequisite` — це DAG.** Цикли розриваються по найслабшому ребру, ітеративно до ациклічності. Без цього агент-генератор не побудує порядок вивчення.
- **Ідемпотентність.** Кожен виклик кешується на `sha256(model+system+prompt+schema)`. Повторний прогін не платить двічі.
- **Gate.** `validate` падає, якщо дослівність цитат < 90 %, покриття юнітів < 95 %, є цикл, висячі ребра або концепт без файлу. `--no-gate` щоб усе одно експортувати.

## Перенесення на KSE

Джерело-специфічний **лише адаптер**. `conceptgraph/adapters/kse.py` — заготовка; правиться під реальні імена файлів KSE. Від `parse()` потрібні п'ять полів: `course_code`, `module_ordinal`, `unit_ordinal`, `asset_kind`, плюс опційні `asset_ordinal`/`part_ordinal`.

```bash
python -m conceptgraph run ~/kse-dump --out ./build-kse --adapter kse
```

Далі `bundle`, `extract`, `consolidate`, `graph`, `export` не змінюються. Форматів вводу зараз підтримано: PDF (`pdftotext`, fallback PyMuPDF), TXT/MD, DOCX, XLSX/XLSM.

## Прогін на реальних даних

Детерміновані стадії й повний реплей сьогоднішніх екстракцій через запакований пайплайн:

```
[scan]      files=282, courses=5, units=72
[textract]  extracted=282, failed=0
[bundle]    units=61, chars=2 388 904, batches=15
[graph]     concepts 405 | links 929 (301 bridge, 174 cross-course) | occurrences 538
[validate]  concepts/unit min 5 median 9 max 12 (7 units outside range)
            quotes verbatim 514/538 = 95.5%
            units covered 61/61 | components 1 [405] | isolated 0
            prerequisite DAG: OK
            GATE: PASSED
[export]    concepts 405, links 929, occurrences 538, seed_sql 1710, html 482 KB
```

`extract` і `consolidate` на реальному API ще не проганялися — потрібен `ANTHROPIC_API_KEY`, якого в цій сесії нема. Логіка викликів, схеми, кеш і ретраї написані й імпортуються, але **перший справжній прогін варто зробити на одному курсі** (`--stop-after extract`), подивитися на `concepts_raw/b01.json` і лише тоді пускати на все.

## Вартість

`run` друкує розбивку по стадіях. Орієнтир на цьому дампі (2.4 млн символів ≈ 600 тис. токенів входу): `extract` на Sonnet — основна стаття, `consolidate` на Opus — десятки викликів на малих входах. Кеш робить повторні прогони майже безкоштовними. Ціни в `config.PRICES`, оновлюй при зміні тарифів.

`--courses AGAI` обмежує прогін одним курсом — так і треба робити перший платний запуск. Обсяг по курсах: AGAI 5 юнітів / 85 тис. символів / 1 батч · AI 8/202 тис./2 · SMM 13/409 тис./3 · NUR 17/459 тис./3 · DBS 18/1.23 млн/8.

Зменшити витрати: `--extract-model claude-haiku-4-5-20251001` (перевір якість цитат — це найперше, що просідає), або `--batch-chars 240000` щоб зменшити кількість викликів.

## Чого тут нема

- **Ембедінги.** Anthropic не дає embeddings API, тому `concepts.embedding` у схемі БД лишається `NULL`. Потрібен окремий провайдер (Voyage, OpenAI, локальний `sentence-transformers`). Це також підняло б якість префільтра злиття — саме там, де лексика має стелю.
- **Запис у БД.** Агент генерує `seed_concepts.sql`; заливка окрема. Додати `--commit` — це один `psycopg` і `ON CONFLICT` (у seed SQL уже є).
- **`chunks`.** Occurrence тримає `rel_path` + цитату, не `chunk_id`. Для `step_materials` у схемі БД потрібне справжнє чанкування.
- **Компетентності.** `Learning outcome: LO1: …` є майже в кожному Notes/Lesson PDF — це найдешевший наступний крок, окрема стадія між `bundle` і `extract`.

## Безкоштовний шлях для силабусів

Силабус — особливий випадок: **назви концептів у ньому вже написані** (клітинка «Content», список тем модуля, рядок після «Lecture N:»). Це задача парсингу, не розуміння. Тому є команда, що не робить жодного запиту до API:

```bash
python -m conceptgraph free ~/Downloads/MIT/Syllabuses --out ./build-free --adapter kse
python -m conceptgraph free ... --sequential-links     # + слабкі ребра за календарем
```

Заміряно на 4 силабусах KSE проти 144 концептів, які я написав руками:

| | детерміновано, $0 | рукописний граф |
|---|---|---|
| концепти | **184** | 144 |
| покриття рукописних назв | **89.6 %** (129/144) | — |
| цитати дослівні | **100 %** (206/206) | 100 % |
| зв'язки | 103 | 254 |
| компоненти | **99** (95 ізольованих) | **1** |

Висновок різкий і його варто прийняти: **детермінізм вирішує концепти, але не зв'язки**. Граф із 95 ізольованими вузлами не годиться для генератора курсів — саме зв'язки є тим, де потрібне судження.

Що `free` дає: назви, дослівні цитати, прив'язку до файлу й уроку, іерархію Topic/Block як `part_of`. Що не дає: визначення (у силабусі їх немає), тип концепту (вгадується регулярками), і зв'язки, крім структурних.

### Локальна модель для решти

`llm_local.py` — два бекенди з тим самим інтерфейсом, що й Anthropic-клієнт, тому `extract.py` і `consolidate.py` не змінюються:

```bash
ollama pull qwen2.5:14b-instruct
python -m conceptgraph run ~/Syllabuses --out ./build --adapter kse \
    --backend ollama --extract-model qwen2.5:14b-instruct
```

Ollama приймає повну JSON Schema в параметрі `format`, тому жорсткий контракт виходу зберігається навіть на маленьких моделях. `OpenAILLM` покриває будь-який OpenAI-сумісний ендпоінт із безкоштовним тиром (Gemini compat, Groq, Mistral) через `response_format: json_schema`.

**Чого я не перевіряв:** якість локальної моделі. Ollama в цій сесії немає. Очікування, яке варто закласти: малі моделі гірші саме в тому, що тут найважливіше — вибір типу зв'язку й відмова від хибних злиттів. Після кожного прогону дивись на кількість коренів prerequisite-підграфа.

### Режим витягу тексту тепер параметр

`-layout` правильний для транскриптів, але **ламає силабуси**: він перемішує сусідні клітинки таблиці в одному рядку, і фраза, суцільна в PDF, у тексті суцільною не існує. Заміряно: дослівність цитат 75.7 % з `-layout` проти 100 % без нього. Команда `free` вмикає сирий режим сама; для `run` є `--raw-text`.

## Повністю безкоштовний агент на Ollama

Так, агент працює без жодної копійки й без ключа. Ollama крутить модель локально — немає лімітів, немає передачі даних наліво.

```powershell
# 1. поставити Ollama:  https://ollama.com/download  (є інсталятор для Windows)
ollama pull qwen2.5:14b-instruct        # ~9 ГБ

# 2. силабуси -> концепти + зв'язки, безкоштовно
python -m conceptgraph run C:\Users\Admin\Downloads\MIT\Syllabuses --out .\build-ollama `
    --adapter kse --backend ollama --extract-model qwen2.5:14b-instruct --raw-text
```

Ollama приймає повну JSON Schema в параметрі `format`, тому жорсткий контракт виходу зберігається й на малій моделі.

### Вибір моделі під залізо

| RAM / VRAM | модель | `--num-ctx` | чого очікувати |
|---|---|---|---|
| 8 ГБ | `qwen2.5:7b-instruct` | 8192 | концепти так, типи зв'язків слабо |
| 16 ГБ | `qwen2.5:14b-instruct` | 32768 | робочий мінімум для зв'язків |
| 32 ГБ+ | `qwen2.5:32b-instruct` | 32768 | найближче до Sonnet |
| GPU 24 ГБ | `qwen3:30b` або `gpt-oss:20b` | 65536 | швидко й якісно |

`--num-ctx` важливий: розмір батча виводиться з нього автоматично (45 % вікна), бо дефолт 160 тис. символів — це ~40 тис. токенів і він переповнить 32k-вікно.

### Що знайшлося, коли я це реально прогнав

П'ять справжніх багів, кожен ловився лише запуском:

1. **`--backend` приймався, але ігнорувався** — `pipeline.run` завжди створював Anthropic-клієнт. Тепер є `_make_llm()`.
2. **Батч переповнював контекст** — 160 тис. символів проти вікна 32k. Тепер `batch_target_chars` виводиться з `local_num_ctx`.
3. **`bundle` викидав усі юніти** — kse-адаптер для окремих силабусів дає `module_ordinal=0`, а модуль 0 вважався орієнтаційним і скіпався. Тепер скіп застосовується лише якщо після нього щось лишиться.
4. **Провал усієї MAP-стадії проліз до гейта** — виглядало як «0 % дослівних цитат», хоча насправді бекенд був недоступний. Тепер `SystemExit` з причиною, і відмова будувати граф, якщо впало більше половини батчів.
5. **`backend=ollama` з `consolidate_model=claude-opus-5`** — тепер назва моделі Claude на локальному бекенді або підмінюється, або дає зрозумілу помилку.

### Чого я так і не перевірив

**Якості локальної моделі.** Ollama в цій сесії немає, поставити не було як. Усі п'ять багів вище знайдені на помилках з'єднання — тобто перевірена *механіка*, а не *результат*. Найризиковіше місце конкретне: R1-арбітраж злиттів. На силабусах KSE префільтр дав 6 кандидатів — `supervised-learning`/`unsupervised-learning`, `definite-integral`/`indefinite-integral`, `l1`/`l2-regularization` — і всі шість треба **відхилити**. Модель, яка їх склеїть, зруйнує граф тихо. Це перше, що варто подивитися очима після першого прогону: `consolidation.json` -> `merges`.

## Покроково: від встановленої Ollama до графа

### 1. Модель

```powershell
ollama serve                      # окреме вікно, хай працює
ollama pull qwen2.5:14b-instruct  # ~9 ГБ; для 8 ГБ RAM візьми qwen2.5:7b-instruct
ollama list                       # переконатися, що вона там
```

### 2. Перевірити налаштування — **перед** будь-яким прогоном

```powershell
python -m conceptgraph doctor --extract-model qwen2.5:14b-instruct
```

Шість перевірок, кожна колись ламалася насправді:

| # | перевірка | чому вона тут |
|---|---|---|
| 1 | Ollama відповідає | найчастіша причина «нічого не працює» |
| 2 | модель встановлена | `pull` без тега дає інше ім'я, ніж очікуєш |
| 3 | **schema-enforced вихід** | якщо модель ігнорує `format`, увесь контракт мертвий |
| 4 | контекст vs розмір батча | батч на 40 тис. токенів у вікно 32k не влазить |
| 5 | **екстракція**: концепти + **дослівність цитат** | перефразована цитата тихо знищує доказовість |
| 6 | **злиття: 6 пар, які треба відхилити** | вирішальна |

Перевірка 6 — головна. Це ті самі шість пар, які лексичний префільтр позначив на твоїх силабусах як майже однакові й **усі шість треба відхилити**: `supervised-learning`/`unsupervised-learning`, `definite-integral`/`indefinite-integral`, `l1`/`l2-regularization`, `differentiable-function`/`differential`, `precision`/`recall`, `demand-curve`/`supply-curve`. Модель, яка їх склеїть, зруйнує граф **без жодної помилки** — тому це єдиний спосіб дізнатися заздалегідь. `doctor` повертає код 1 і називає кожне хибне злиття.

### 3. Якщо перевірка 6 провалилася

Не міняй промпт — бери сильнішу модель, або **розділи бекенди**. Екстракція терпить малу модель, консолідація ні:

```powershell
# екстракція локально й безкоштовно, консолідація на сильнішій моделі
python -m conceptgraph run ...\Syllabuses --out .\build --adapter kse --raw-text `
    --backend ollama --extract-model qwen2.5:14b-instruct `
    --consolidate-model qwen2.5:32b-instruct
```

### 4. Прогін на одному курсі, потім на всьому

```powershell
python -m conceptgraph run ...\Syllabuses --out .\build --adapter kse --raw-text `
    --backend ollama --extract-model qwen2.5:14b-instruct --stop-after extract
```

Подивись `build\concepts_raw\b01.json` очима: концепти справжні? цитати дослівні? Далі прибери `--stop-after` — стадії кешуються, екстракція не переробиться.

### 5. Що читати в результаті

```powershell
python -m conceptgraph report --out .\build
```

Три числа вирішують усе:

- **дослівність цитат** — нижче 90 % гейт падає; це або перефразування, або не той режим витягу тексту;
- **компоненти** — має бути 1; багато компонент означає, що консолідація не зшила граф;
- **корені prerequisite-підграфа** — має бути кілька справді фундаментальних понять. Якщо коренем стоїть щось складністю 4, тип зв'язку вибрано неправильно (та сама пастка, що двічі спрацювала на силабусах KSE).

І окремо подивись `build\consolidation.json` -> `merges`. Якщо там з'явилися пари з перевірки 6 — модель усе одно склеїла їх на реальних даних, попри чистий `doctor`.
