# Curriculum Study-Planner Agent

An MCP-integrated agent for a 4-course AI-prep track (Calculus, Linear
Algebra, Machine Learning, Probability essentials — course codes
`CALC`/`LINALG`/`ML`/`PROB`). It reads a student's course plan from an
Obsidian vault, validates it against real per-course data (ECTS, syllabus
prerequisites, extracted concepts) through a custom MCP server, and writes a
concrete review back into the vault.

Built for an MCP-integration assignment: Part A is the existing **Obsidian
Local REST API** MCP server; Part B is the custom **`curriculum-mcp`**
server; the agent (**Claude Agent SDK**) ties both into one workflow. See
[`docs/`](docs/) for the full write-up (tool contracts, design rationale,
defense checklist).

## Architecture

```
                         ┌─────────────────────────────┐
                         │   Claude Agent SDK  (agent)  │
                         │  study_planner_agent.py      │
                         └───────────┬─────────┬────────┘
                    MCP (stdio)      │         │      MCP (http)
                    ┌────────────────┘         └──────────────────┐
                    ▼                                              ▼
        ┌───────────────────────┐                    ┌──────────────────────────────┐
        │   curriculum-mcp      │                    │  obsidian-local-rest-api MCP  │
        │  (this repo, own      │                    │  (Obsidian plugin, own        │
        │   process, 4 tools)   │                    │   process, built-in server)   │
        └──────────┬────────────┘                    └───────────────┬──────────────┘
                   │ reads locally                                    │ HTTP + bearer token
                   ▼                                                  ▼
        output/dataset/concept_graph.json                  Obsidian app + demo vault
        (generated by conceptgraph; local                  (obsidian_demo_vault/,
         dataset, no network at runtime)                    StudyPlan.md)
```

Both MCP servers are separate processes from the agent and from each other,
and are started independently (see below).

## Prerequisites

- Python 3.10+
- [Obsidian](https://obsidian.md) desktop app
- [Node.js](https://nodejs.org) (for `npm`, to install the Claude Code CLI below)
- [Claude Code](https://code.claude.com) installed (`npm install -g
  @anthropic-ai/claude-code`) and logged in (a Pro/Max/Team subscription
  works — no separate API key needed), **or** an `ANTHROPIC_API_KEY` from
  [console.anthropic.com](https://console.anthropic.com) if you'd rather bill
  a pay-per-token account instead

The dataset (`output/dataset/concept_graph.json`) is already generated and
committed — regenerating it is optional and needs nothing beyond this repo's
own `conceptgraph` package (no LLM, no API key, no Ollama; see below).

```bash
pip install -r requirements.txt
```

## Configuration

```bash
cp .env.example .env
```

Then edit `.env`:

| Variable | Required? | Meaning |
|---|---|---|
| `OBSIDIAN_API_KEY` | Yes | From Obsidian's Local REST API plugin settings (see below). |
| `OBSIDIAN_BASE_URL` | Yes | `http://127.0.0.1:27123` (see the HTTP-vs-HTTPS note below). |
| `ANTHROPIC_API_KEY` | No | Leave unset to use the ambient Claude Code login; set only for pay-per-token API billing instead. |

`.env` is gitignored — never commit it. Two more variables are optional and
have working defaults (`CURRICULUM_DATA_DIR`, `STUDY_PLANNER_MODEL`) — see
the comments in `.env.example`.

### Setting up the Obsidian demo vault (Part A)

1. Install Obsidian, then **Open folder as vault** on `obsidian_demo_vault/`
   in this repo (a dedicated demo vault — never point this at a personal
   vault, per the assignment's safety guidance).
2. **Settings → Community plugins → Browse** → install **"Local REST API"**
   (by coddingtonbear) → Enable.
3. **Settings → Local REST API** → copy the **API key** into `.env`
   (`OBSIDIAN_API_KEY`) → enable **"Non-encrypted (HTTP) Server"** (the
   default HTTPS endpoint uses a self-signed certificate that the Node-based
   Claude Code CLI has no simple way to trust; the HTTP endpoint is
   loopback-only — 127.0.0.1, never reachable off the machine — so this is a
   safe trade-off for a local demo; see `docs/DESIGN_RATIONALE.md`).
4. Verify the connection independently of the agent:
   ```bash
   python scripts/check_obsidian_connection.py
   ```
   This connects as a real MCP client, lists the plugin's tools with their
   schemas, and reads `StudyPlan.md` — confirming Part A's "discover and call
   a tool" requirement in isolation.

## Running independently (as required for the defence)

**Custom MCP server** — start on its own, in its own terminal/process:

```bash
python -m mcp_servers.curriculum_mcp.server
```

It loads `output/dataset/concept_graph.json` + `course_metadata.json` once at
startup and serves over stdio. No network calls at runtime.

**The agent** (spawns/connects to both MCP servers itself — the command
above does not need to be run first, the SDK launches `curriculum-mcp` as a
subprocess and connects to the already-running Obsidian plugin over HTTP):

```bash
python -m study_planner.study_planner_agent [note.md]
```

`note.md` is optional (default `StudyPlan.md`) — pass a different vault note
to vary the input, or a nonexistent one to reproduce the failure demo:

```bash
python -m study_planner.study_planner_agent NoSuchPlan.md
```

The agent prints every tool call and result as it runs, then writes
`<note> Review.md` back into the vault.

## Repository layout

```
conceptgraph/            concept-graph extraction pipeline (pre-existing tool;
                          see conceptgraph/README.md). Produces the dataset
                          curriculum-mcp serves.
sources/                  the 4 source syllabus PDFs
output/dataset/           the generated, committed dataset (concept_graph.json)
mcp_servers/curriculum_mcp/   the custom MCP server (Part B)
study_planner/            the Claude Agent SDK driver
obsidian_demo_vault/       the dedicated demo vault (StudyPlan.md, generated
                          Review notes)
scripts/                  setup/connectivity check scripts
docs/                     tool contracts, design rationale, defense checklist
```

## Regenerating the dataset (optional — already committed)

```bash
python -m conceptgraph free sources --out output --adapter syllabus --sequential-links
```

Deterministic, zero-cost, no API key or network call. See
`docs/MCP_ASSIGNMENT_PLAN.md` for why this path was chosen over an
LLM-enriched one, and `conceptgraph/README.md` for the pipeline itself.
